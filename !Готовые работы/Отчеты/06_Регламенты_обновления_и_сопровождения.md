# Раздел 6. Регламенты обновления и технического сопровождения ИС

**Тема:** Автоцентр «Плюс»
Скрипты: `Проекты/SQL/06…08`

## 6.1. Регламент обновления структуры БД

Файл `06_UpdateStructure.sql` — имитация обновления версии ИС без потери данных:

1. Добавление поля Note в таблицу Customer (ALTER TABLE … ADD);
2. Расширение поля Name таблицы Product до NVARCHAR(250);
3. Создание новой таблицы OrderHistory (история статусов заказов) с FK и каскадным удалением;
4. Добавление CHECK-ограничения CHK_Order_TotalAmount (TotalAmount >= 0);
5. Контрольные запросы сохранности данных после обновления.

## 6.2. Организация файловой структуры БД

Файл `07_FileGroups.sql`:

- создание файловой группы FG_Indexes и вторичного файла данных (ndf);
- перенос индекса IX_Customer_INN в FG_Indexes (WITH DROP_EXISTING);
- контроль структуры через sys.database_files.

Файловая структура: mdf (PRIMARY) — данные, ndf (FG_Indexes) — индексы, ldf — журнал транзакций.

## 6.3. Регламент резервного копирования

Файл `08_BackupRestore.sql`:

| Тип копии | Периодичность | Команда |
|---|---|---|
| Полная (FULL) | Еженедельно, воскресенье 02:00 | BACKUP DATABASE … WITH COMPRESSION |
| Разностная (DIFF) | Ежедневно, кроме воскресенья | BACKUP DATABASE … WITH DIFFERENTIAL |
| Журнал транзакций (LOG) | Каждые 2 часа | BACKUP LOG … |

Проверка целостности: `RESTORE VERIFYONLY`.

## 6.4. Регламент восстановления

Тестовое восстановление в отдельную БД AutoCenterPlusDB_Test:

```sql
RESTORE DATABASE AutoCenterPlusDB_Test
FROM DISK = 'C:\SQLBackups\AutoCenterPlusDB_FULL.bak'
WITH MOVE …, RECOVERY, REPLACE;
```

Поддерживается цепочка восстановления на момент времени (PITR): FULL (NORECOVERY) → DIFF (NORECOVERY) → LOG (STOPAT).

## 6.5. График сопровождения

| Операция | Периодичность | Ответственный |
|---|---|---|
| Полное копирование | Воскресенье 02:00 | Администратор БД |
| Разностное копирование | Ежедневно 02:00 | Агент SQL Server (задание) |
| Копирование журнала | Каждые 2 часа | Агент SQL Server |
| Тестовое восстановление | Еженедельно | Администратор БД |
| Проверка целостности (DBCC CHECKDB) | Еженедельно | Администратор БД |
| Обновление статистики | После массовых изменений | Администратор БД |
| Обновление структуры БД | По регламенту релиза | Разработчик ИС |

## 6.6. Выводы по разделу

Разработаны и апробированы регламенты: обновление структуры БД без потери данных, файловые группы для разделения данных и индексов, трёхуровневая стратегия резервного копирования (FULL/DIFF/LOG) с проверкой и тестовым восстановлением. Обновление структуры подтверждено контрольными запросами: данные всех таблиц сохранены.
