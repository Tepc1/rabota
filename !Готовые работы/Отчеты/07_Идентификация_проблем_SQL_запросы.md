# Раздел 7. Идентификация технических проблем. SQL-запросы

**Тема:** Автоцентр «Плюс»
Скрипт: `Проекты/SQL/09_Queries_Views_Procedures.sql`

## 7.1. Постановка задачи

Идентифицировать технические проблемы расчёта полной стоимости заказа и оптимизировать часто используемые выборки с помощью VIEW и хранимых процедур.

## 7.2. Запрос расчёта полной стоимости заказа

**Требование ТЗ (Ф4):** стоимость = Σ(цена × норма × количество) по всем материалам и операциям спецификации каждой позиции заказа.

Реализация — соединение Order → OrderDetail → Product → Specification с коррелированными подзапросами по SpecMaterial и SpecOperation; итог по позиции: `Quantity × (MaterialsCostPerUnit + OperationsCostPerUnit)`.

## 7.3. Представление v_OrderFullCost

Часто используемая выборка вынесена в VIEW. Выявленная проблема: коррелированные подзапросы в SELECT выполнялись для каждой строки — риск Table Scan и рост времени ответа при увеличении объёма данных.

**Оптимизация:** подзапросы заменены на OUTER APPLY с агрегацией — запрос стал set-based, план выполнения использует Index Seek по индексам IX_OrderDetail_OrderProduct и IX_Product_Name.

VIEW используется клиентским приложением (OrderForm) и API (OrdersController).

## 7.4. Хранимые процедуры

| Процедура | Назначение |
|---|---|
| sp_CalculateOrderCost | Расчёт полной стоимости заказа (@OrderId, @TotalCost OUTPUT) через v_OrderFullCost |
| sp_UpdateOrderTotal | Обновление поля TotalAmount заказа агрегатом из VIEW |

Преимущества: единая точка бизнес-логики, кэширование плана, снижение сетевого трафика, защита от SQL-инъекций (вызов по имени с параметрами).

## 7.5. Анализ плана выполнения

Методика: SSMS → Include Actual Execution Plan (Ctrl+M), SET STATISTICS IO/TIME.

| Показатель | До оптимизации | После оптимизации |
|---|---|---|
| Подзапросы в SELECT | Скалярные, построчные | OUTER APPLY, set-based |
| Доступ к данным | Table Scan (риск) | Index Seek по индексам |
| Число обращений к таблицам норм | N × строки | 1 агрегатный проход |

После изменений обновлена статистика: UPDATE STATISTICS OrderDetail, SpecMaterial, SpecOperation.

## 7.6. Выводы по разделу

Идентифицирована и устранена техническая проблема построчного вычисления стоимости: выборка переведена в VIEW v_OrderFullCost с OUTER APPLY, бизнес-логика расчёта инкапсулирована в хранимых процедурах. Оптимизация подтверждена анализом планов выполнения и статистикой IO/TIME.
